Flow UX - Gestion de tarjetas y suscripciones

Mapa del comportamiento propuesto para que el usuario pueda eliminar tarjetas guardadas, cambiar tarjetas asociadas a pagos recurrentes y entender cada bloqueo con una accion clara.

Abrir prototipo Ver resumen de comportamiento
Entrada principal Mis tarjetas guardadas y Mis suscripciones son accesos cruzados, no pantallas aisladas.
Accion clave Cambiar metodo de pago desde una suscripcion abre un selector de tarjetas con opcion de nueva tarjeta.
Eliminacion Eliminar intenta completar la accion y solo bloquea si no hay alternativa segura.
Copy No se usa la etiqueta "No borrable"; se muestra contexto y siguiente paso.
Pantalla / entrada Decision de sistema Resultado correcto Bloqueo contextual

1. Entrada

Mis tarjetas guardadas

Lista tarjetas, estado predeterminado, uso en suscripciones y acciones por fila.

Mis suscripciones

Lista suscripciones con fecha de renovacion, tarjeta asociada y acciones.

->

2. Acciones

Eliminar tarjeta

La accion esta siempre visible junto a la tarjeta.

Seleccionar predeterminada

Marca otra tarjeta como metodo por defecto del usuario.

Cambiar metodo de pago

Desde suscripciones, abre modal con tarjetas guardadas y "Añadir nueva".

->

3. Decisiones

Tarjeta sin suscripcion

Se puede borrar directamente.

Vinculada + hay predeterminada

Se borra y la suscripcion pasa a la tarjeta predeterminada.

Vinculada + sin predeterminada

Se bloquea con mensaje y acceso a Mis suscripciones.

->

4. Resultados

Tarjeta eliminada

La lista se actualiza y se informa la accion completada.

Suscripcion actualizada

La tarjeta asociada queda cambiada para la siguiente renovacion.

Resolver bloqueo

El usuario va a Mis suscripciones para asignar otra tarjeta o cancelar la renovacion.

Flujo A - Cambiar tarjeta de suscripcion

  1. El usuario entra en Mis suscripciones.
  2. Ve la propiedad Tarjeta asociada bajo la fecha de renovacion.
  3. Pulsa Cambiar metodo de pago.
  4. Selecciona una tarjeta guardada o añade una nueva.
  5. La suscripcion se actualiza y se muestra confirmacion.

Flujo B - Eliminar tarjeta vinculada

  1. El usuario pulsa Eliminar junto a una tarjeta.
  2. El sistema comprueba si esta vinculada a pagos recurrentes.
  3. Si existe otra tarjeta predeterminada, reasigna la suscripcion a esa tarjeta.
  4. Elimina la tarjeta original.
  5. Muestra el mensaje de reasignacion completada.

Flujo C - Bloqueo contextual

  1. El usuario intenta eliminar una tarjeta vinculada.
  2. No existe otra tarjeta predeterminada disponible.
  3. Se muestra el mensaje de bloqueo con explicacion.
  4. El usuario puede ir a Mis suscripciones o cerrar.
  5. Desde Mis suscripciones cambia tarjeta o cancela renovacion.

Flujo D - Definir predeterminada

  1. El usuario entra en Mis tarjetas guardadas.
  2. Pulsa Seleccionar como predeterminado junto a una tarjeta.
  3. El sistema actualiza el metodo predeterminado.
  4. La etiqueta Predeterminada se mueve a la tarjeta elegida.
  5. El nuevo default queda disponible como fallback de suscripciones.
Este flujo asume que el backend puede conocer las suscripciones que dependen de cada tarjeta y puede reasignar una suscripcion al metodo de pago predeterminado cuando se elimina su tarjeta actual. Si esa reasignacion requiere confirmacion explicita o autenticacion adicional, debe añadirse como paso intermedio.
